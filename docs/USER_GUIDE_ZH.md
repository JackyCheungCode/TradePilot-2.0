# TradePilot 系统操作手册（中文）

> 版本：TradePilot 2.0 · 文档基线：当前 `develop` 路由与页面实现  
> 适用对象：销售、外贸业务、运营、管理人员及系统管理员  
> 说明：本手册按当前系统已登记的页面、路由和可见功能整理。不同账号的权限、数据量、外部服务连接状态会影响实际可用操作。标注“需配置/视连接状态”的功能，必须先完成对应配置；“即将开放”不代表当前可操作。

---

## 1. 系统概览与使用原则

TradePilot 是面向外贸业务的工作平台，覆盖全球潜客发现、线索与客户管理、客户沟通、销售机会、报价与订单、贸易单证、发运、收款，以及 AI Agent 和系统配置。

### 1.1 推荐业务主流程

1. 配置企业资料、产品资料、业务规则及外部 API。
2. 通过全球潜客发现获取目标企业线索，或手动录入线索。
3. 在潜客数据中检查来源、评分和企业信息，将合适记录送入 CRM。
4. 在商机/线索模块持续跟进；建立客户档案和联系人关系。
5. 创建销售机会并推进销售阶段。
6. 根据客户需求制作报价单；客户确认后创建销售订单。
7. 根据订单安排发运，记录运输、包装、跟踪和异常。
8. 登记收款、分配到账款并进行对账。
9. 在贸易单证中心生成、编辑、预览和管理业务文件。
10. 在经营驾驶舱查看业务汇总；通过沟通工作区和小雅辅助跟进。

### 1.2 通用操作原则

- 先确认当前客户、联系人、商机或订单，再执行创建、编辑和确认操作。
- 保存草稿与正式确认/签发不是同一动作；正式操作前核对金额、币种、数量、地址、日期和条款。
- 列表页通常用于搜索、筛选、排序和进入记录；详情页用于查看单条记录及执行后续操作。
- 若页面显示加载失败、权限不足或外部服务不可用，先检查登录状态、权限和系统设置，不要重复提交可能已成功的业务动作。
- 金额优先按页面显示的币种及基础币快照规则理解；未配置汇率的外币不应自行推算为统一金额。
- 重要业务资料应保持来源可追溯，避免重复建立客户、联系人和订单。

## 2. 登录、顶部栏与全局导航

### 2.1 登录

访问系统后进入登录页，按页面提示输入账号凭证。系统可能要求额外验证：
- TOTP 动态验证码；
- 恢复码；
- 已注册设备支持时的 WebAuthn/生物识别验证。

若验证失败，检查验证码时效、设备时间和浏览器兼容性；不要将密码、验证码或恢复码分享给他人。登录会话失效时重新登录。

### 2.2 顶部栏

- **TradePilot 标识**：返回应用主入口。
- **小雅入口**：打开/关闭 AI 助手侧面板；小雅用于辅助分析和任务交互。
- **主题设置**：可选择跟随系统、白色、浅灰、深灰或深色主题。
- **账户菜单**：进入个人设置或退出登录。
- **帮助**：打开本系统中文操作手册页面（帮助中心）。

### 2.3 左侧导航分组

| 分组 | 菜单 | 用途 |
|---|---|---|
| 工作台 | 总览 | 查看经营指标、市场分布、销售漏斗、物流及 AI 运行概况 |
| 情报与商机 | 线索数据、商机 | 管理发现数据及销售线索 |
| 客户管理 | 联系人、客户档案、销售机会 | 维护联系人、企业客户及销售机会 |
| 客户沟通 | 沟通 | 集中处理客户会话与全渠道消息 |
| 贸易业务 | 报价单、销售订单、贸易单证、物流发货、收款管理、产品管理 | 完成外贸交易履约 |
| 设置与系统 | 贸易工具、AI 与 Agent、系统设置、安全中心 | 配置工具、AI 能力、业务规则和安全选项 |

在窄屏设备上，左侧导航会以覆盖层方式展开；选择页面后导航自动收起。

## 3. 工作台：总览（/dashboard）

### 用途
总览汇集客户、联系人、线索、商机、报价/订单、发运、收款、产品和 Agent 运行等数据，帮助管理者了解业务状态。

### 操作步骤
1. 打开“工作台 → 总览”。
2. 等待数据加载；若出现错误提示，先检查网络、登录会话和数据权限。
3. 使用时间范围筛选查看近期、较长周期或全部数据。
4. 使用国家/市场筛选缩小分析范围。
5. 在市场指标切换项中选择要观察的对象，结合地图和图表查看分布。
6. 点击可交互指标或模块入口（若页面提供）进入对应业务记录继续处理。
7. 使用刷新操作重新读取数据。

### 指标理解
- 总览是聚合视图，不代替业务模块中的单据详情和财务核对。
- 客户、线索、商机、订单等统计口径取决于记录状态及筛选条件。
- 外币金额只有在记录存在可用基础币金额快照时才可纳入统一金额汇总；未配置汇率的外币不参与合计。
- Agent 运行数量不等同于已完成的业务成果，需结合任务状态和结果明细判断。

## 4. 全球情报与线索管理

### 4.1 全球外贸智能潜客发现（/prospect-discovery）

该页面采用五步流程：

1. **数据源与平台选择**：选择可用的数据源/平台。数据源是否可用取决于服务接入及账号配置。
2. **动态参数配置**：按所选数据源提供的真实参数表填写搜索条件；不同平台字段可能不同。
3. **执行全网搜索**：核对目标国家、关键词、平台和执行范围后启动任务。
4. **AI 智能清洗与打分**：系统对发现结果进行整理、去重/质量处理和潜客评分；评分仅作筛选辅助，仍需人工判断。
5. **决策人穿透与入库**：查看可获得的决策人/联系人信息，确认后将合适记录纳入后续 CRM 流程。

页面提供“历史任务”和“潜客数据”入口。任务执行可能需要等待外部平台返回数据。

### 4.2 历史任务（/prospect-history）

- 查看历史发现任务、任务编号、搜索条件、渠道、状态和结果数量。
- 状态可能包括排队中、执行中、已完成、部分完成、失败、已取消或已暂停。
- 打开单个任务可查看执行日志和发现结果。
- 若任务部分完成，检查日志及结果后再决定是否调整条件重新执行。
- 重新执行前先检查是否已有相同任务结果，避免重复数据。

### 4.3 潜客数据（/prospect-data）

- 查看从不同来源采集的潜客记录及企业信息。
- 使用搜索、筛选、排序和分页定位目标企业。
- 核对企业名称、国家、网站、联系方式、来源、评分和状态。
- 记录状态可能包括待处理、已送入 CRM、已废弃或手动移除。
- 将合格记录送入 CRM 前，先检查是否已存在相同客户/线索。
- 对无效、重复或不符合目标画像的记录，按页面提供的管理操作处理。

### 4.4 商机/线索（/leads）

- 查看线索编号、企业、国家、联系方式、来源和跟进状态。
- 可通过新建入口手动录入线索；从潜客转入的记录应保留来源信息。
- 按状态推进跟进，例如新建、联系中、已确认、已转换或已失效（具体选项以页面为准）。
- 线索转化前核实企业是否已存在于客户档案，避免重复建档。
- 线索是潜在业务对象；转化为正式客户或销售机会后，应在对应模块继续维护。

## 5. 客户关系管理（CRM）

### 5.1 客户档案（/accounts）

客户档案用于维护企业客户主数据。

**常见流程**
1. 进入“客户档案”，搜索客户名称或使用筛选条件定位记录。
2. 打开详情检查企业名称、国家/地区、行业、状态和关联信息。
3. 新建客户时填写必要企业信息及联系方式；保存前检查重复记录。
4. 在详情页维护客户信息，并查看相关联系人、商机或业务关联（以页面实际展示为准）。
5. 客户状态变化时及时更新，避免将失效客户继续用于新业务。

### 5.2 联系人（/contacts）

联系人是客户企业中的个人联系对象。

**常见流程**
1. 进入联系人列表，按姓名、客户或联系方式查找。
2. 新建联系人时尽量关联正确的客户档案。
3. 填写姓名、职位、邮箱、电话等可用信息。
4. 保存后进入详情核对归属客户和联系方式。
5. 联系人离职或信息失效时，更新状态或资料；不要随意删除仍有关联业务的历史联系人。

### 5.3 销售机会（/opportunities）

销售机会用于管理从需求识别到成交的销售过程。

**常见流程**
1. 创建销售机会并关联客户；如有联系人，选择对应联系人。
2. 填写机会名称、预计金额、币种、概率、预计成交日期和负责人等页面要求字段。
3. 根据实际沟通推进销售阶段，记录下一步行动。
4. 更新预计金额和成交概率时，以最新客户反馈为依据。
5. 成交后按业务流程创建报价单或销售订单；失败机会应更新状态并保留原因。

## 6. 客户沟通与小雅

### 6.1 沟通工作区（/communications）

沟通页面用于集中处理客户会话和全渠道消息。

1. 打开“客户沟通 → 沟通”。
2. 从客户/会话列表选择目标客户。
3. 查看消息历史和上下文，确认沟通对象。
4. 在回复区域撰写消息，核对发送渠道及内容后发送。
5. 需要继续跟进时，结合客户档案、联系人和商机更新业务记录。
6. 移动端可使用客户列表返回入口切换会话。

可用渠道和消息能力取决于已连接的消息服务与账号授权。发送失败时先检查渠道连接状态，避免重复发送。

### 6.2 小雅 AI 助手（顶部小雅入口、/agent）

- 通过顶部小雅入口打开侧面板，或进入 Agent 工作区进行较完整的任务交互。
- 在输入框说明目标、对象、国家/市场、期望结果和限制条件。
- 如页面提供 Agent、执行模式或渠道选择，应在提交前核对。
- 发送后关注任务状态、进度、工具调用结果及错误提示。
- 对 AI 生成的客户信息、市场判断、邮件或建议，必须人工核验后再用于正式业务。
- 不要向 AI 输入密码、验证码、银行卡完整信息或其他不应共享的敏感数据。

## 7. 销售交易管理

### 7.1 报价单（/quotes）

1. 进入报价单列表，搜索或筛选目标报价。
2. 新建报价单，选择客户及相关业务信息。
3. 添加产品/服务明细，核对数量、单价、币种、税费、折扣和总额。
4. 填写有效期、交付/贸易条款及备注等必要信息。
5. 保存草稿后进入详情复核。
6. 对外发送或正式确认前，检查客户抬头、明细、金额和有效期。
7. 修改已保存报价时，留意修订/版本记录及客户确认状态。

报价单详情的历史版本、事件记录可能受数据权限和关联数据可用性影响；若无法加载，先确认主报价记录和访问权限。

### 7.2 销售订单（/sales-orders）

1. 根据已确认的报价或客户订单创建销售订单。
2. 核对客户、产品明细、数量、价格、币种、交付日期及贸易条款。
3. 保存草稿并复核。
4. 按页面提供的确认操作完成订单确认；确认后部分字段可能受到状态规则限制。
5. 后续从订单进入发运、收款和单证流程。
6. 订单取消或变更应遵循企业内部审批规则，并保留原因。

### 7.3 产品管理（/products）

- 产品列表用于搜索、筛选和维护产品主数据。
- 新建产品时填写名称、SKU、分类、品牌、规格、单位及页面要求字段。
- 规格属性、变体和分类等基础字典通常在系统设置中维护。
- 编辑产品前检查其是否已被报价或订单引用。
- 停售/归档与删除含义不同：停售用于停止新业务选用，历史单据仍需保留可追溯信息。

## 8. 贸易单证中心

### 8.1 单证中心（/documents）

单证中心按交易单据、商业单据、物流单据等类别组织制作入口。当前页面列出的首期可用类型包括报价单、形式发票（PI）、销售合同、商业发票、装箱单和装运指示。页面标注“即将开放”的类型尚不可使用。

### 8.2 单证工作台（/documents/studio）

1. 从单证中心选择单据类型，或打开即时单据入口。
2. 选择业务来源（例如订单或发运批次），按页面提示载入数据。
3. 检查企业抬头、客户信息、产品明细、金额、币种、包装和运输信息。
4. 在编辑画布中调整内容与版式。
5. 保存草稿并预览；确认内容无误后再按页面提供的流程生成正式文件。
6. 生成后到“已生成单据”查看记录和历史版本。

### 8.3 模板中心（/documents/templates）

管理预设模板、个人模板和企业模板。选择模板时确认单据类型、语言、品牌信息及展示字段；修改模板前建议保留可复用版本。

### 8.4 企业信息（/documents/company-profile）

维护单据中使用的企业卖方抬头、注册地址、联系方式和收款账户。企业资料发生变化后，应检查新生成单据是否已读取最新资料。

### 8.5 已生成单据（/documents/generated）与预览（/documents/:id）

- 在已生成单据列表中查找草稿、已签发文件及历史版本。
- 打开单据预览，核对页面显示、字段、金额和文件内容。
- 正式文件应按企业文件管理制度归档；不要将草稿误认为已签发文件。

## 9. 物流发运与收款

### 9.1 物流发货（/shipments）

1. 从销售订单或页面提供的业务来源创建发运记录。
2. 填写运输方式、计划发运日期、包装/箱型、数量、费用及跟踪信息。
3. 核对收货方、地址、订单明细和发运数量。
4. 保存后进入发运详情持续更新物流节点。
5. 出现延误、货损或其他异常时，按页面字段记录异常并及时通知相关人员。
6. 需要单据时，从发运详情使用生成单据入口。
7. 编辑或取消前确认发运状态及其对订单、单证的影响。

### 9.2 收款管理（/payments）

1. 创建收款记录，关联客户及对应订单/业务。
2. 填写收款方式、日期、币种、金额、手续费和银行/账户信息。
3. 保存后检查收款详情。
4. 对预收款或未分配余额，进入分配页面（/payments/:id/allocate），选择对应应收业务并核对分配金额。
5. 登记退款时核实原收款、退款金额、日期和原因。
6. 根据银行流水核对到账金额、手续费和实际净收金额。
7. 对账信息保存后复核差异；收款记录不等于银行实际到账，需以银行凭证为准。

## 10. 贸易工具（/trade-tools）

贸易工具中心用于访问外贸工作所需的辅助工具。具体工具是否可执行取决于对应服务、API 凭证和权限配置。

- 先阅读工具说明及所需输入。
- 输入国家、币种、产品、运输或其他参数时核对单位和格式。
- 执行前确认是否会调用第三方服务或产生费用。
- 对工具输出的汇率、时间、运输信息、翻译或市场数据，关注来源和更新时间。
- 工具返回错误时检查 API 配置、额度和参数，不要将失败结果作为正式业务依据。

## 11. AI 与 Agent 管理（/ai-agents）

AI 与 Agent 中心集中管理 AI 模型、Agent、外部 Agent、Skills、Tools、任务调度、安全与历史记录。页面通过 URL 参数选择具体分区，例如 `/ai-agents?section=skills`。

### 11.1 AI 总览与模型/供应商
查看 AI 平台概况并配置可用模型与供应商。使用前确认供应商凭证、模型标识和调用权限；不同模型的能力、费用和可用区域可能不同。

### 11.2 Agent 管理
维护专业 Agent 的定义、启用状态和任务能力。配置变更后应通过低风险任务验证，再用于正式业务。

### 11.3 第三方 Agent 接入
登记外部 Agent 的连接信息和授权范围。只授予完成任务所需的最小权限，定期复核连接状态。

### 11.4 Skills 管理
管理 Agent 可调用的技能定义/资源。注册技能前检查来源、版本、说明、输入输出契约和权限要求；启用后先测试，再开放给业务任务使用。

### 11.5 Tools 管理
管理可供 Agent 使用的工具能力。工具权限应按风险和用途配置；涉及写入、外部发送或费用的工具需特别谨慎。

### 11.6 任务与调度
查看任务执行记录及调度状态。排查失败任务时检查输入、权限、外部服务和执行日志；避免在不清楚幂等性的情况下重复触发写操作。

### 11.7 权限与安全
检查 Agent、Skill、Tool 的授权边界和执行限制。遵循最小权限原则，不要把管理密钥写入技能说明或提示词。

### 11.8 AI 历史记录与小雅形象
查看历史交互和任务上下文；可在支持的设置区调整小雅形象。历史结果仅用于追溯，不能替代业务单据的正式记录。

> 当前页面中“运行监控”区标记为后续接入；不要将其描述为已完整开放的监控能力。

## 12. 系统设置（/settings）

系统设置采用业务领域分组。可用设置以当前账号权限及页面实际呈现为准。

### 12.1 产品设置
- 产品分类与产品线：维护多级分类。
- 规格属性：定义可复用属性。
- 规格模板：按分类组合产品属性。
- 产品变体规则：维护变体组合和 SKU 规则。
- 认证类型：维护 CE、FCC、RoHS 等认证字典。

### 12.2 CRM 设置
按客户、联系人、线索、商机等领域维护业务字段、状态、选项及相关规则。调整前先评估对已有记录、筛选条件和报表的影响。

### 12.3 企业档案
维护企业法定身份、注册地址、联系方式、经营信息、单据卖方抬头和收款银行账户。此处信息可能被单据生成流程调用。

### 12.4 单据配置
- 单据类型管理：配置单据来源、字段校验、编辑权限和正式确认规则。
- 模板管理：按类型和语言管理版式、展示字段及默认模板。
- 通用设置：维护报价单和销售订单共享规则。
- 报价单设置：维护有效期、修订和客户确认规则。
- 销售订单设置：维护确认、锁定、履行和取消规则。

### 12.5 发运与收款设置
- 共享基础设置：币种和贸易术语。
- 发运设置：运输规则、运输方式、箱型、包装、费用、跟踪节点和异常字典。
- 收款设置：收款方式、账户、汇率/手续费、应收账龄、信用证、退款核销和对账规则。
- 部分设置可能仅提供规则配置，并不代表已连接银行或承运商的实时服务。

### 12.6 API 集成
统一维护外部服务凭证和连接信息。保存前核对服务商、环境、权限和额度；密钥仅放在专用安全配置中，不要复制到普通备注或文档。

### 17.2 列表页的标准操作方法

列表页的具体控件由各模块实现决定，不能假设每张表都具备完全相同的功能。实际操作时按以下顺序检查页面：

1. **搜索**：使用页面提供的关键词输入框；优先使用编号、名称、邮箱、SKU 等明确字段。
2. **筛选**：检查状态、日期、国家、客户、负责人等筛选条件；清除筛选后再判断记录是否缺失。
3. **排序**：点击可排序列标题（若该列提供排序交互），确认升序/降序标识。
4. **分页**：查看当前页码和每页条数；切换分页后注意所选记录通常只属于当前选择范围，不能默认跨页保留。
5. **选择记录**：勾选行或表头选择框后，观察页面是否出现选择计数或批量操作栏。若没有出现，先确认是否真的选中、是否有权限以及当前页面是否支持批量动作。
6. **批量动作**：只执行界面实际显示的动作。导出、归档、删除、状态更新等并非所有模块都提供；不要将“已勾选”理解为已经执行。
7. **行级动作**：查看行尾操作或打开详情；行级编辑、删除和详情入口可能因模块不同而异。
8. **刷新**：重新加载数据后，确认筛选条件、页码和选择状态是否保留。
9. **导出**：若页面提供导出，导出前核对筛选范围、字段和数据敏感级别。
10. **删除/作废**：先检查关联业务、状态和影响；财务及贸易单据优先使用作废/归档等有记录的业务动作，不应擅自删除历史凭证。

**TradePilot 标准数据表（TpDataTable）的真实交互规则：**

- 只有页面开启了“可选择”能力时，才会显示行选择框；某些记录还可能因业务条件被禁选。
- 勾选至少一条记录后，批量操作栏才会出现。默认提供“导出所选”；若该页面配置了归档表，还会出现“归档所选”；其他批量按钮由页面单独注册，并非全站统一提供。
- “归档所选”会把记录标记为归档并从当前列表移除，不是物理删除。组件没有通用的“批量删除”按钮；删除/作废应查看模块自己的行操作或详情动作。
- 表头复选框选择/取消的是当前页可选记录。跨页翻页时已选记录会保留；但当逻辑筛选范围变化时，组件会清空旧选择，防止把上一组筛选结果误操作。
- 工具栏会显示已选数量，并提供“清除选择”。批量操作成功后选择会清空；失败时显示错误反馈，记录仍保持选中以便检查或重试。
- 行尾有“操作”菜单的模块，会在每行显示溢出菜单；可用动作由该模块传入。点击行本身可能打开右侧详情面板，面板支持上一条/下一条；有完整详情页的模块还会显示“打开完整详情”。
- 开启列设置的表格可隐藏/显示非必需列、上移/下移列顺序、恢复默认列。必需列和主列不能隐藏；长文本列或默认隐藏列初始可能不显示。
- 列偏好会保存在浏览器本地，并尝试同步到当前用户资料；云端同步失败时，本地设置仍可继续使用。不同表格通过各自的设置键隔离。
- 表格有服务端排序回调时，排序会提交给页面数据查询；没有排序回调时不要假设点击列头一定会改变服务端结果。
- 分页器提供每页 10、20、50、100 条。右侧详情面板可在服务端分页场景下跨页切换上一条/下一条。
- 标准表格导出为 CSV，导出所选记录和当前可见列；字段会进行 CSV 安全处理。导出范围不等于全部数据库记录。

**排查“勾选后没有操作栏”：** 确认页面是否启用了行选择、是否至少勾选一条可选记录、该行是否被业务条件禁选、当前是否仍处于加载/错误状态。若选择计数存在但批量栏缺失，记录模块名称、筛选条件、选中数量和截图反馈给管理员。自定义表格页面不一定使用以上标准交互。

### 17.3 CRM 字段与业务关系

**线索（/leads/new）**的录入表单按业务信息分组，字段涵盖：
- 线索属性：类型、状态、评级。
- 企业信息：公司名称、网站、公司类型、行业、规模、电话、邮箱和社交账号。
- 联系人信息：姓名、职位、是否决策人、个人邮箱、手机、WhatsApp 和社交账号。
- 联系偏好：首选渠道、最佳联系时间、语言。
- 地址信息：国家、州/省、城市、街道、邮编、区域和时区。
- 来源与需求：来源、来源说明、发现记录/任务关联、产品类别、需求描述、预计规模和紧急程度。
- 跟进与合规：负责人、最近/下次联系时间、联系次数、是否回复、是否拒绝联系、标签、备注及无效原因。

填写建议：公司名称与国家是识别线索的重要依据；邮箱/电话应区分企业公共联系方式和个人联系方式；拒绝联系标记必须尊重，不得通过其他渠道绕过。来源任务 ID 仅用于关联系统中已有任务，不要自行编造。

**客户（/accounts）**是企业主档，可维护法定名称、客户类型、行业、网站、联系方式、国家地区和地址、注册/税务编号、结算币种、付款条件、贸易术语、信用额度/账期、来源线索、负责人、销售团队、税务分类、价格表、交付方式、银行资料、标签及归档状态。编辑客户时特别核对法定名称、税号、发票邮箱、收货/账单地址和银行信息。

**联系人（/contacts）**可维护姓名、称谓、头像、状态、所属客户、主要联系人标记、角色/决策角色、职位、部门、汇报关系、任职时间、邮箱/电话/分机/WhatsApp/Fax、额外联系方式、社交账号、地址、语言、时区、首选沟通渠道、最佳联系时间、生日、备注及勿扰标记。联系人必须关联正确客户；主要联系人变更前确认客户内部实际关系。

**销售机会（/opportunities）**包含机会名称/编号、客户和主要联系人、阶段、状态、金额/币种、成交概率、预计成交日期、来源、竞争对手、下一步、销售团队/负责人、预测类别、优先级、预计数量/毛利、产品明细、标签和跟进记录。阶段推进应基于客户真实进展；赢单/输单时补全实际金额或失败原因，不能只为改善报表而修改阶段。

### 17.4 报价、订单、发运与收款的状态控制

**报价单：** 报价明细支持产品行、分组行和备注行；产品行需核对 SKU、名称、描述、数量、单位、单价、折扣、税率、成本参考和 HS 编码等信息。报价合计可能受税费模式、折扣上限、费用是否计税等共享设置影响。编辑报价时检查当前版本、有效期和客户确认状态。

**销售订单：** 订单明细除产品、数量、价格、折扣和税率外，还可能包含客户 SKU、规格、确认数量、原产国、HS 编码、包装数量、箱数、净重、毛重和体积。订单可包含交付计划/付款计划；订单来源报价应复核成交快照。订单确认或锁定后，部分字段可能不再允许直接修改。

**发运：** 发运状态按页面定义的顺序推进：草稿 → 待订舱 → 已订舱 → 已装柜 → 已报关 → 已开船 → 在途 → 已到港 → 已清关 → 已签收；取消只允许在早期状态（草稿、待订舱、已订舱、已装柜）按当前规则执行。系统允许的状态变更受当前状态限制，不能任意跳级。运输资料包括货代、承运人、订舱号、SO 号、运输方式、追踪号/链接、船名航次、起运港/目的港、中转港、截单/截港日期、ETD/ATD/ETA/ATA、签收日期、免柜期，以及提单、集装箱、包装、重量和体积资料。

**收款：** 收款状态包括草稿、待确认、已确认、部分核销、已核销、已退回、已作废。收款方式包括 T/T、L/C、D/P、D/A、PayPal、Western Union、现金、支票及其他。分配时核对付款币种金额、分配币种金额、汇率/折算值、关联订单和付款计划节点。可分配订单须满足页面规则（如订单处于有效/完成等可分配状态）；分配总额不得超过实际可分配余额。退款、退回和作废不是同一业务含义，应按实际银行资金流处理。

### 17.5 贸易单证：可用范围、来源与版本

当前单证工作台内置类型为报价单、形式发票（PI）、销售合同、商业发票、装箱单和装运指示。其来源并不相同：
- 报价单、PI、销售合同：以销售订单/交易资料为来源，核对买卖双方、产品和成交条款。
- 商业发票：以发运批次为来源，按本次实际发运数量计算。
- 装箱单：以本次发运包装、箱数、重量、体积和货品为来源。
- 装运指示：以发运批次和运输资料为来源。

模板有语言和版本快照；修改模板不会自动改写已经生成的历史单据。单据预览页应核对当前版本、状态、语言、币种、内容、合计、模板快照及 PDF 生成信息。草稿、待审核、已批准、已签发、已发送、已作废、已归档是不同状态；正式对外使用前必须确认状态与文件版本。

**产品表单（/products/new、/products/:id/edit）字段组：** 产品基础资料包括 SKU、中文/英文名称、产品类型（实物/服务/组合）、产品状态、品牌、型号、条码、客户料号、标签、分类、产品系列和负责人；规格资料包括描述、材料、颜色、尺寸、属性和认证；计量包装包括基本/销售/采购单位、单位换算、包装层级、MOQ、订货倍数、净重/毛重、尺寸、体积、箱规、托盘和集装箱装载参考；贸易合规包括 HS 编码、中英文报关品名、申报要素、原产国、出口退税率、增值税率、法定单位、监管条件、检验标志和危险品标记/类别；价格包括成本价/币种、标准价/币种、最低价和价格有效期；供应与销售包括供应商行、可销售/可采购、税务分类、销售描述、交期、保修和保质期；资料附件包括多语言、主图、图库、附件、变体、库存开关、默认仓库、安全库存和内部备注。保存前检查 SKU 唯一性、单位换算、包装重量和 HS 编码；危险品资料必须由合规人员复核。

**报价单金额核算：** 报价行可分为产品、分组和备注；产品行可设置数量、单位、单价、行折扣、税率、成本参考、HS 编码及“可选项”。可选产品行不计入默认产品小计。单据级折扣受产品小计上限约束；费用行可分别设置金额、是否计税和税率。总额由产品小计、单据折扣、费用和税额共同计算，税务模式、默认税率、折扣上限和费用计税规则来自共享/报价设置。修改税率或费用配置后，应重新核对报价总额和客户确认版本。

**销售订单行与付款计划：** 订单行除产品/分组/备注类型外，还包含 SKU、客户 SKU、产品名称/描述/规格、订购数量、确认数量、单位、单价、折扣、税率、成本、HS 编码、原产国、包装数量、箱数、净重、毛重、体积、供应商、行状态、拒绝原因、行备注和分批计划。分批计划可维护到期日、计划数量、已发货数量及触发条件。订单级付款计划可维护节点名称、比例、到期日、触发条件、应付金额、已付金额和状态。保存或确认订单前，检查产品行合计、折扣/税费、付款比例是否与合同约定一致，以及发运计划数量是否超过确认数量。

**发运详情字段组补充：** 页面按订舱与运输、提单资料、报关清关、费用与保险、跟踪与异常、备注与附件分组。JSON 型集装箱、费用、跟踪节点和单据清单字段有明确结构键名；若页面提供结构化输入控件，优先使用控件，不要手工输入不合法 JSON。计划日期与实际日期应分开维护；异常标记开启时补充异常类型和说明。提单状态、报关状态、目的国清关状态属于单证/清关业务字段，不等同于发运主状态。

**收款登记与分配：** 收款主记录状态为草稿、待确认、已确认、部分核销、已核销、已退回或已作废。收款列表可切换“收款/应收”视图，并按关键词、状态、币种和国家等条件查看数据。分配表单包含订单、付款计划节点、分配类型（定金/尾款/全款/预收/其他）、收款币种金额、分配金额和分配日期。订单只有符合可分配状态时才会出现在候选项中；跨币种分配必须核对付款金额和订单币种金额，不能仅比较数字大小。分配前检查剩余未分配余额，避免重复核销。

### 17.6 AI 与 Agent 的实际配置说明

AI 与 Agent 中心使用 URL 参数切换分区：
- `/ai-agents`：AI 总览；
- `?section=models`：模型与供应商；
- `?section=agents`：Agent 管理；
- `?section=connections`：第三方 Agent 接入；
- `?section=skills`：Skills 管理；
- `?section=tools`：Tools 管理；
- `?section=tasks`：任务与调度；
- `?section=security`：权限与安全；
- `?section=monitoring`：运行监控（当前标记为后续接入，不是已开放功能）；
- `?section=appearance`：小雅形象；
- `?section=history`：AI 历史记录。

**Skills 注册：** 当前界面支持从 Git 仓库来源登记 Skill，并上传 Skill 文件包；配置会显示来源类型、注册/同步状态、启用状态、技能契约和安全审查信息。检查重点包括 skill.json 契约、入口、所需工具、网络主机、数据范围、密钥需求、副作用、超时/内存/输出限制，以及安全扫描发现。注册成功不等于已允许执行；执行能力还受隔离运行时和人工审核建设状态限制。不要将“已登记/已同步”误解为任意代码均可安全运行。

**Tools 权限：** Tool 风险策略分为只读自动执行、执行前人工审批、禁止调用。注册来源可包含系统内置、外部连接和注册工具；修改策略后检查策略来源和实际生效状态。外发消息、写入 CRM、提交单据或产生费用的工具，不应按只读权限放行。

**第三方连接：** 支持 MCP、REST API / OpenAPI 3 和 Webhook 协议类型；配置名称、端点、认证方式、Token 或自定义 Header、能力范围后，先执行连接测试。连接状态应区分已连接、异常和待验证；密钥不得写入普通描述字段。

**任务监控：** 任务状态可能包括排队中、待执行、执行中、已暂停、等待审批、已完成、失败和已取消。打开任务详情检查目标、计划、结果、错误、预计/实际成本、事件、日志及关联发现任务/记录。等待审批的任务必须由有权限人员处理，不能通过重复发起任务绕过审批。

### 17.7 贸易工具逐项说明

贸易工具中心当前可见工具：
1. **HS Code 智能归类**：根据商品描述预测美国 10 位 HTS 编码。输入应包含材料、用途、结构、功能和关键技术参数；预测编码必须由报关/合规人员复核。
2. **出口关税预估**：查询基础、优惠和附加关税结构。必须核对出口国、进口国、原产地、商品编码、申报价值和币种；估算不等于正式税费意见。
3. **贸易实体制裁筛查**：检查企业或个人是否与受限名单记录匹配。近似名称可能误报或漏报，应核验国家、地址、别名、名单来源和匹配依据。
4. **美国 CBP 海关裁决检索**：按商品和业务语义检索美国海关历史裁决。裁决结论需检查发布日期、商品事实和适用范围，不能直接套用于不同商品。
5. **网站抓取与 AI 企业背调**：通过公开网页抓取企业官网信息并整理公开联系方式。只处理公开可访问资料；核对网站归属、抓取时间和来源，AI 摘要不可替代人工尽调。

### 17.8 系统设置中心的子领域与配置边界

系统设置不是单一表单，而是按业务域切换配置面板。当前设置中心包括以下主领域：

- **产品**：分类与产品线、规格属性、规格模板、产品变体规则、认证类型、计量单位与换算、包装层级、贸易与报关、销售与采购、文件与多语言、产品数据规则。
- **商机**：商机阶段、状态及销售机会相关选项和规则。
- **联系人**：称谓、联系人角色、部门、职位、联系方式类型、社交平台、沟通偏好、语言、联系人状态、来源、授权/同意类型、数据规则和自定义字段。
- **客户**：客户类型、客户等级、行业、企业规模、生命周期状态、业务类型、地址类型、付款条件、付款方式、交易币种、贸易术语、交付方式、销售团队、客户价格组、信用等级、客户来源、风险分类、数据规则和自定义字段。
- **线索**：线索类型、生命周期、评级、来源渠道、失效原因、公司类型、行业、公司规模、需求紧急程度、资格评估、分配规则、跟进时效、重复线索规则、转换规则、数据规则和自定义字段。
- **企业档案**：本企业法定身份、注册资料、地址、联系资料、经营信息、卖方单据抬头和银行账户。
- **单据配置**：共享通用规则、报价单专属规则、销售订单专属规则、单据类型和模板。
- **发运与收款**：共享币种/贸易术语、发运规则、收款方式/账户/手续费/汇率/账龄/信用证/退款和对账规则。
- **API 集成**：集中管理外部服务凭证和连接参数。保存密钥时使用安全凭证字段，不要把密钥写入普通文本或截图。

部分配置项的集成状态可能是“已连接”“仅配置”或“待接入”。“仅配置”表示字典/规则可维护，不代表外部系统已经实时连通。修改客户、线索或联系人字典前，评估已有记录、筛选、报表和自动分配规则的影响；建议先在少量测试记录验证。

### 17.9 CRM 设置的维护方法

1. 进入系统设置并选择客户、联系人或线索领域。
2. 在左侧选择需要维护的子目录，例如客户类型、联系人角色、线索来源或自定义字段。
3. 查看现有选项名称、编码、配置、顺序和启用状态。
4. 新增或编辑时，保持编码稳定、名称清楚；如果字段用于状态流转或数据匹配，避免随意更改已有编码。
5. 需要停用选项时优先使用“切换状态”，不要直接删除仍被历史记录引用的字典项。
6. 对自定义字段，明确字段类型、是否必填、选项值和帮助说明；先验证创建/编辑表单及筛选是否能正确读取。
7. 对线索分配、跟进时效、重复检测和转换规则，修改后用测试线索验证规则命中结果。

配置域中的 connected/config-only 状态是集成能力提示，不是数据质量或业务审批结果。

### 17.10 个人设置的分区说明

个人设置页当前包含六个分区：
- **个人资料**：头像与账户基本信息。
- **登录与安全**：Passkey、多因素认证和恢复方式的入口；安全凭证的实际管理仍以安全中心为准。
- **外观与显示**：主题、语言、时区和格式偏好。
- **通知偏好**：任务完成、AI 分析、潜客发现和系统通知开关。
- **工作偏好**：默认落地页、列表每页条数和默认市场。
- **隐私与账户管理**：个人设置导出及账户相关信息。

工作偏好中的默认列表条数与单个表格的分页状态可能是不同设置；若页面提供单独分页器，以当前列表实际显示为准。更改主题后可立即观察页面层级；更改默认落地页后，下次进入系统时再核对。

### 17.11 AI 模型与内置 Agent 配置补充

模型供应商配置页当前包含 Cloudflare Workers AI、OpenRouter、OpenAI、Anthropic、Google Gemini，以及多个兼容 OpenAI API 的供应商选项。供应商目录不代表已配置或已开通；每个供应商仍需完成端点、模型和凭证配置，并通过连接测试。按任务指定模型时，检查该模型是否仍启用、供应商凭证是否有效及是否存在调用额度。

内置 Agent 配置可见的专业角色包括全球买家开发、市场研究、企业调查、潜客评估、多语言销售、客户跟进和贸易合规等。Agent 配置中可能涉及系统提示词、说明、模型引用、Skill 选择和 Tool 选择。修改系统提示词或能力绑定后，应先执行低风险验证，避免将未审查的外部 Skill/Tool 直接开放给真实客户业务。

### 17.12 页面异常与业务安全检查表

执行任何有业务副作用的操作前，使用以下检查：
- 对象：客户、联系人、商机、报价、订单、发运或收款是否选对？
- 范围：是否有正确的记录编号、筛选条件和批量选择数量？
- 状态：当前状态是否允许该动作？是否需要审批？
- 金额：币种、数量、税费、折扣、汇率和分配余额是否一致？
- 外部影响：是否会发送邮件/消息、调用第三方 API、创建远端记录或产生费用？
- 幂等性：上一次提交是否已经成功？先查记录/日志，不要盲目重复提交。
- 追溯：是否保留业务来源、操作时间、版本和原因？

### 17.13 页面覆盖核对说明

本手册逐项列出当前 `src/app/router.tsx` 中的 58 个路由声明（其中根路径 `/` 会重定向到 `/dashboard`），包括列表、新建、详情、编辑、分配和兼容跳转。路由存在只代表前端有页面入口，不代表账号一定有访问权限，也不代表外部服务已经连接。对于设置中心内部由 `section` 或页面状态切换的子分区，需结合对应设置页面的实际配置项继续阅读第 11、12 节。
