### P1 — release governance and provenance

- GitHub `develop` branch protection is currently disabled.
- The current `deploy.yml` in `develop` is manual-only and defaults to `hold`, which is the intended release gate.
- Root cause of the unplanned deployments: Cloudflare Workers Builds had an active GitHub trigger watching `develop` and running `npm run build && npm run worker:validate`, followed by `npm run worker:deploy` on every push.
- That Cloudflare production trigger has now been deleted. A fresh API check confirmed the Worker has no remaining build triggers. The GitHub manual-only release workflow remains intact.
- Before the trigger was removed, its in-flight build completed and deployed Worker version 818 to 100% traffic. Cloudflare build metadata ties version 818 to commit `4baeb285e0b4c32486b613a3172d048804e6fd87`. This was an unplanned production deployment, not an approved release. The corresponding GitHub CI later passed, but browser E2E and database migration acceptance remain outstanding.
- The Cloudflare Workers Build configuration was removed with its trigger; the manual GitHub release workflow is now the only configured release path found in the audited repository. Continue to verify no new deployment appears after subsequent develop commits.
